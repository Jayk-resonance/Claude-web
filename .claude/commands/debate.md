너는 하나의 논쟁적 질문을 찬성(PRO)/반대(CON) 양측으로 토론시키고 중립 심판(JUDGE)이
결론을 내리는 **멀티에이전트 토론**을 진행한다. 각 역할은 Agent 도구로 띄운 **독립 서브에이전트**다
(별도 API 키·요금 없이 현재 세션에서 동작).

## 주제

$ARGUMENTS

주제가 비어 있으면, 찬반이 명확히 갈리는 **단일 명제(yes/no 형태)** 주제를 사용자에게 먼저 물어라.
"~ 전망은?", "어느 쪽이 유리한가?" 같은 비-찬반/다지선다형이면, 찬반형으로 다듬도록 제안하라.

## 진행 순서 — 서브에이전트 5개를 순차 실행

각 단계는 Agent 도구 1회 호출(`subagent_type: "general-purpose"`)이며, **앞 단계의 결과 텍스트를
다음 단계 프롬프트에 그대로 넣어** 전달한다. 변론 단계는 프롬프트에 "웹 검색으로 최신 사실·규제·
사례를 확인하고 출처를 제시하라"를 포함시킨다.

| 단계 | 역할 | model | 입력으로 받는 것 |
|------|------|-------|------------------|
| 1 | PRO 입론 | `sonnet` | 주제 |
| 2 | CON 반박 | `sonnet` | 주제 + PRO 입론 |
| 3 | PRO 재반박 | `sonnet` | 주제 + CON 반박 + 자신의 입론 |
| 4 | CON 재반박 | `sonnet` | 주제 + PRO 재반박 + 자신의 반박 |
| 5 | JUDGE 종합 | `opus` | 주제 + 위 4개 전체 (웹 검색 없이 평가만) |

> effort는 Agent 도구로 따로 지정할 수 없어 모델 기본값을 따른다. 모델 차등(변론 Sonnet / 종합 Opus)만 적용한다.

## 페르소나 (각 서브에이전트 프롬프트에 역할 지시로 포함)

- **PRO**: 토론의 '찬성' 측 변론자. 긍정 입장을 가장 설득력 있게 변론하라. 구체적 근거·메커니즘·
  사례와 출처를 제시하고, 가장 강한 반대 논거를 미리 반박하라. 입장을 흐리지 말고 일관되게 찬성하라.
- **CON**: 토론의 '반대' 측 변론자. 부정 입장을 가장 설득력 있게 변론하라. 동일 형식. 일관되게 반대하라.
  (반박 단계에서는 상대 주장을 구체적으로 겨냥해 반박한 뒤 자기 입장을 강화하라.)
- **JUDGE**: 중립 토론 심판. 양측 주장을 읽고 각 측의 강점·약점을 평가한 뒤 증거 기반의 균형 잡힌
  결론을 제시하라. 미리 기울지 말고 불확실성은 명시하라. **발언 순서나 마지막 발언권은 주장의 강도를
  의미하지 않는다 — 오직 논거의 질과 근거로만 판단하라.** 출력: (1) 찬성 핵심·강점·약점
  (2) 반대 핵심·강점·약점 (3) 종합 판단과 근거 (4) 남은 불확실성.

## 최종 출력

5개 마크다운 섹션으로 정리해 사용자에게 보여줘라:
`## 찬성 입론 (PRO)` / `## 반대 반박 (CON)` / `## 찬성 재반박 (PRO)` / `## 반대 재반박 (CON)` /
`## 종합 판단 (JUDGE)`.
