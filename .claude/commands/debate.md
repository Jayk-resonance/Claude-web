하나의 논쟁적 질문을 찬성(PRO)/반대(CON) 양측으로 토론시키고 중립 심판(JUDGE)이 결론을
내리는 **멀티에이전트 토론**을 진행한다. 각 역할은 `.claude/agents/` 에 정의된 **독립
서브에이전트**이며(모델·페르소나가 각 파일에 고정되어 서로 격리됨), Agent 도구로 순차
호출한다. 별도 API 키·요금 없이 현재 세션에서 동작한다.

## 주제

$ARGUMENTS

주제가 비어 있으면, 찬반이 명확히 갈리는 **단일 명제(yes/no 형태)** 주제를 사용자에게 먼저
물어라. "~ 전망은?", "어느 쪽이 유리한가?" 같은 비-찬반/다지선다형이면 찬반형으로 다듬도록
제안하라.

## 진행 순서 — 서브에이전트 5회 순차 호출

각 단계는 Agent 도구 1회 호출이다. `subagent_type` 에 아래 에이전트 이름을 지정하고,
**앞 단계의 결과 텍스트를 다음 호출 프롬프트에 그대로 넣어** 전달한다.

| 단계 | subagent_type | 프롬프트에 넣어 전달할 입력 |
|------|---------------|------------------------------|
| 1 | `debate-pro`   | 주제 |
| 2 | `debate-con`   | 주제 + 1단계(PRO 입론) |
| 3 | `debate-pro`   | 주제 + 2단계(CON 반박) + 1단계(자신의 입론) |
| 4 | `debate-con`   | 주제 + 3단계(PRO 재반박) + 2단계(자신의 반박) |
| 5 | `debate-judge` | 주제 + 1~4단계 전체 |

> 모델·페르소나는 각 에이전트 파일에 고정되어 있다(`debate-pro`/`debate-con` = Sonnet,
> `debate-judge` = Opus). 호출 시 `model` 을 따로 지정하지 마라.

## 최종 출력

5개 마크다운 섹션으로 정리해 사용자에게 보여줘라:
`## 찬성 입론 (PRO)` / `## 반대 반박 (CON)` / `## 찬성 재반박 (PRO)` / `## 반대 재반박 (CON)` /
`## 종합 판단 (JUDGE)`.
