# S0 스크리닝

## 입력

매물 번호 또는 폴더명 (예: `003`, `003-example.com`).
번호만 주어지면 저장소 최상단에서 `00X-*` 폴더를 찾는다.

## 절차

1. **대상 폴더를 확정한다.** 없으면 사용자에게 폴더명을 묻는다.
2. **`screenshots/`에 파일이 있는지 확인한다.** 비어 있으면 스크린샷을 넣어달라고 안내하고 중단한다.
3. **`deal-screener` 서브에이전트를 띄운다** (Agent 도구, `subagent_type: "deal-screener"`, `run_in_background: false`).

   프롬프트에 반드시 포함할 것:
   - 매물 폴더의 절대 경로
   - 사용자가 함께 준 텍스트 정보(리스팅 설명, Q&A 등)가 있으면 그 내용
   - "`<폴더>/00-screen.md`를 작성하라"

4. **결과를 사용자에게 전달한다.** 판정·총점·결정적 요인·미확인 항목을 간결히.
5. **`pipeline.md`를 갱신한다.** 해당 매물 행을 추가하거나 상태를 업데이트.

## 판정별 안내

| 판정 | 다음 안내 |
|---|---|
| 🟢 PASS | `/dd <번호>`로 IC 메모 작성을 제안 |
| 🟡 HOLD | 보류 사유와 재검토 조건을 알림 |
| 🔴 KILL | 사유를 명확히 전달. 미련 갖게 하지 말 것 |

## 주의

- **스크리닝을 메인 대화에서 직접 하지 마라.** 서브에이전트로 분리하는 이유는 비용이 아니라 **본 대화 맥락 보호**다. 매물 5~10건을 훑을 때 스크린샷 판독 과정이 메인 컨텍스트를 오염시키면 안 된다.
- 사용자가 명백히 KILL인 매물에 미련을 보이면, 루브릭 근거를 들어 담백하게 재확인하되 논쟁하지 마라.
