# S1 정밀 실사 (IC 메모)

## 선행 조건

`00-screen.md`가 존재하고 판정이 PASS 또는 HOLD여야 한다.
KILL 매물에 대해 호출되면 사유를 알리고, 사용자가 그래도 원하는지 확인한다.

## 절차

### 1단계 — 컨텍스트 로드
`_knowledge/` 전체 + 매물 폴더의 `00-screen.md` + `screenshots/` + 사용자가 제공한 추가 자료(Q&A, 리스팅 텍스트, 사이트 캡처).

### 2단계 — 메모 작성
`_templates/ic-memo.md` 구조로 `<폴더>/01-ic-memo.md`를 작성한다.

**작성 원칙:**
- **리스팅 표기와 실제 12개월 실적의 차이를 §1.1 맨 앞에 놓는다.** 이게 대개 가장 중요한 발견이다.
- 모든 추정치에 **근거와 오차범위**를 붙인다. `_knowledge/valuation-model.md`의 정직성 규칙을 따른다.
- 레버는 **시간당 가치 순**으로 정렬한다. 절대 금액 순이 아니다.
- 시나리오는 **3개 + 확률**. 단일 숫자 금지.
- §4에 **"패스도 합리적인 선택인지"**를 반드시 명시한다. 판정을 팔지 마라.
- 확인하지 못한 것은 **검증 한계** 섹션에 명시한다. 추정으로 메우지 마라.

### 3단계 — 레드팀 검증 (필수)
`deal-skeptic` 서브에이전트를 띄운다 (`subagent_type: "deal-skeptic"`, `run_in_background: false`).
프롬프트에 IC 메모의 절대 경로를 넘긴다.

### 4단계 — 반론 반영
반환된 반론을 심각도별로 처리한다:

| 심각도 | 처리 |
|---|---|
| `KILL` | **판정 자체를 재작성.** 반론이 옳다면 결론을 바꾼다 |
| `MATERIAL` | 해당 숫자·조건을 수정하고, 수정 사실을 메모에 남긴다 |
| `MINOR` | 반영하되 별도 표기 불필요 |

살아남은 반론은 메모 말미에 **"§6 반론 검토"** 섹션으로 정리한다:
어떤 반론이 제기됐고, 무엇을 수정했고, 무엇을 기각했으며 왜인지.

⚠️ **레드팀 반론을 무비판적으로 수용하지도 마라.** 근거가 약한 반론은 기각하고 그 이유를 적는다.

### 5단계 — 전달
사용자에게 **판정 + 선결조건 + 레드팀이 바꾼 것**을 요약한다.
메모 전문을 되풀이하지 마라.

웹 아티팩트로 보고 싶어 하면 만들어준다 (artifact-design 스킬 로드 후).
