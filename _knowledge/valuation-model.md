# 밸류에이션 · 시나리오 모델

## 기본 단위

소형 온라인 자산의 표준 가격 표기:
```
매도가 = 월 순익(SDE) × 배수
```
- 통상 범위: **월 30~40배** = **연 2.5~3.3배**
- 회수기간(개월) = 매도가 ÷ 월순익

⚠️ **"월 순익"은 고정비 차감 후여야 한다.**
리스팅의 표기 수익은 대개 **매출**이며, 호스팅·유료 라이선스·이메일 도구 비용이 빠지지 않은 경우가 많다.

```
실질 순이익 = 월 매출 − 월 고정비
```

월 $105 자산에 고정비 $30이면 순이익은 $75 — **배수가 3.3x에서 4.6x로 뛴다.**
고정비를 확인하기 전의 배수는 **잠정치**로 표기하고, 매도자에게 ①금액 ②표기 수익이 차감 전인지 후인지를 반드시 질의한다.
(→ `operability.md` §3)

## 배수 조정 요인

| 배수를 **높이는** 요인 | 배수를 **낮춰야 하는** 요인 |
|---|---|
| 수익원 다변화 | 단일 수익원 |
| 트래픽 소스 분산 (구글 의존 낮음) | 단일 트래픽 소스 |
| 12개월+ 안정적 추세 | 짧은 실적 이력 / 큰 변동성 |
| 이전 용이성 | 계약 락인 · 승계 불확실 |
| 소유주 의존도 낮음 (관리 시간 0) | 소유주 개인 브랜드 의존 |
| 인간 집필 · 자연 백링크 | AI 콘텐츠 · 인위적 링크 |
| tier-1 트래픽 비중 높음 | 저CPM geo 비중 높음 |
| | 최근 급등 (지속성 의심) |

## 존속기간과 IRR — 배수만으로는 부족하다

배수는 **회수기간**만 알려주고, **자산이 그만큼 사는지**는 말해주지 않는다.
`duration.md`로 기대 존속기간을 산출한 뒤 **두 가지를 반드시 병기**한다.

**① 안전마진 (하방 테스트)**
```
안전마진 = 기대 존속기간(년) ÷ 연배수
```
"매각이 불가능한 최악의 경우에도 원금을 회수하는가." 1.5 미만이면 KILL.

**② 자본 IRR (수익률)**
```
현금흐름: −매입가, +연 순이익 × 기대 존속기간, (+매각 시 매각가)
```

기대 존속기간에 따라 IRR이 얼마나 흔들리는지 반드시 표로 보여줄 것:

| 자산 수명 | IRR (예: 3.3배 매입, 현상 유지) |
|---|---:|
| 3년 | −6% |
| 5년 | +15% |
| 7년 | +23% |
| 10년 | +28% |

⚠️ **IRR은 "자본 수익률"이며 인수자의 노동은 포함돼 있지 않다.**
라벨을 명확히 붙일 것 — 노동을 뺀 수익률을 노동이 포함된 것처럼 읽으면 과대평가된다.

## 시나리오 모델 구조

**3개 시나리오 × 각각의 확률**로 기대값을 낸다. 절대 단일 숫자로 제시하지 말 것.

```
[각 시나리오]
  12개월 후 월순익      = 현재 월순익 + Σ(레버별 추가 수익)
  1년차 누적 현금흐름   = 추가 월수익 × 12 × 램프계수(0.5)
  예상 매각가           = 12개월 후 월순익 × 배수
  Equity 순증           = 예상 매각가 − 매입가
  총 가치창출           = 1년차 누적 CF + Equity 순증
  시간당 가치           = 총 가치창출 ÷ 투입 시간
```

**램프계수 0.5**: 수익이 즉시 붙지 않고 1년에 걸쳐 서서히 오르므로 평균 절반만 실현.

**배수는 시나리오별로 다르게** 적용: 수익원이 다변화될수록 배수도 오른다.
예) Bear 33x / Base 34x / Bull 38x

## 시나리오 정의 원칙

| | 구성 |
|---|---|
| **Bear** | 인수자가 **확실히 할 수 있는 레버만** 실행. 어려운 레버는 0으로 계상 |
| **Base** | 어려운 레버가 **절반 정도 성공** |
| **Bull** | 어려운 레버까지 성공 |

**시나리오별 배수에 존속기간을 반영할 것.** 수익원이 다변화되면 배수가 오르는 이유는
단순히 "안정적이라서"가 아니라 **존속기간이 늘어나기 때문**이다 — 단일 실패점이 줄어드니까.

⚠️ **Bear를 "아무것도 안 함"으로 두지 말 것.** Bear는 "실행은 하되 어려운 레버가 실패한 경우"다.
"아무것도 안 함"은 별도의 다운사이드 케이스이며, 그 경우 매도자와 동일한 수익으로 수렴한다.

## 시간당 가치 — 레버 배분용 지표

레버별로 계산해 **어느 레버가 시간을 가장 효율적으로 쓰는지** 정렬한다.

### ⚠️ 이 지표를 급여와 비교하지 말 것

두 가지 이유로 apple-to-apple이 아니다:

1. **급여는 한계시급이 아니다.** 회사에서 한 시간 더 일한다고 그만큼 더 받는 구조가 아니므로,
   시급을 부업의 기회비용으로 쓰는 것은 경제적으로 틀렸다. 그 시간의 실제 대안은 여가이지 추가 급여가 아니다.
2. **탐색·학습 시간은 비용이 아니라 역량 투자다.** 딜을 보며 얻는 시장 감각은
   다음 딜의 판단 정확도로 이어진다. 이걸 매몰비용처럼 차감하면 시스템 자체가 정당화되지 않는다.

**따라서 이 지표는 절대 기준(go/no-go)이 아니라 상대 비교용이다:**
- 같은 시간이면 어느 레버부터 손대야 하나
- 이 레버는 절대 금액이 커도 시간이 너무 많이 드는가

절대 판단이 필요하면 **자본 IRR**(위 섹션)과 **학습가치·옵션가치**를 따로 놓고 본다.

### 다년 보정
1년차 표는 셋업 시간이 전액 반영돼 불리하다.
2년차부터는 월 3~5시간 유지로 현금흐름을 회수하므로, 2~3년 관점 시간당 가치는 상당히 높아진다.
반드시 병기할 것.

## 추정의 정직성 규칙

1. **오차범위 ±40%를 명시**한다. 정밀 예측이 아니라 가치 동인(driver)을 드러내는 추정이다.
2. **미검증 가정은 그렇게 표기**한다 (예: "제휴 전환율 3%는 미검증 가정").
3. **민감도가 큰 변수 2~3개를 지목**한다. 대개 트래픽 규모와 전환율.
4. 최대 불확실 변수는 **인수 후 소액 실측으로 해소 가능한지** 함께 적는다.
5. 스크린샷 판독으로 재구성한 수치는 **재구성값임을 명시**하고, 공시된 합계·평균에 맞춰 조정한다.

## 협상 프레이밍

**"가격이 부당하다"보다 "리스크를 내가 떠안는다"가 강한 레버다.**

깨끗하고 내구적인 자산에 통상 배수가 붙어 있으면 그건 바가지가 아니다.
할인 근거는 다음에서 찾는다:
- 리스팅 프레이밍과 실제 12개월 실적의 괴리
- 수익 변동성 이력 (원인 미규명이면 더 강함)
- 승계·계약 리스크를 인수자가 부담
- 구조적 천장 (저CPM geo 등)

**부가자산(유튜브·소셜·이메일리스트)은 광고 수익 배수와 분리해 협상**한다.
"광고 수익엔 낮은 배수, 부가자산엔 별도 프리미엄" 구조.
