# 근거·보안·저작권 점검

## 정량 주장 카드

각 수치는 다음 여섯 항목을 채운 뒤 사용한다.

1. 지표 이름
2. 기존값과 현재값
3. 측정 기간과 표본 수
4. 계산식 또는 측정 방법
5. 근거 파일·화면·업무 기록
6. 수치 공개 승인 여부

예: `주 2회 × 회당 90분 → 회당 15분, 8주간 16회 측정, 작성자 작업 로그 기준`. 근거가 없으면 “약 83% 절감”처럼 계산한 값을 확정 성과로 쓰지 않는다.

## 사실 상태

| 상태 | 초안 처리 |
|---|---|
| 공개 근거로 검증 | 단정 가능, 링크 또는 파일 위치 기록 |
| 사용자 확인 필요 | `[확인 필요]`로 질문과 함께 남김 |
| 추론 | 아이디어 메모에만 보관, 본문 제외 |
| 공개 금지 또는 권리 불명 | 삭제·마스킹하거나 비공개 근거로 대체 |

## 업로드 전 보안 게이트

- 사내 기밀, 미공개 경영정보, 내부 전략·기술 사양을 제외한다.
- 이름, 이메일, 사번, 연락처, 고객·거래 정보를 제거한다.
- 내부 시스템의 원본 데이터, DB 덤프, 로그를 올리지 않는다.
- 화면의 이름, 금액, 식별번호, URL 파라미터, 브라우저 탭·알림까지 확인한다.
- 경쟁작 이미지와 내부 운영 공지 전문은 공개 저장소에 복제하지 않는다.
- 비식별만으로 공개 승인이 되는 것은 아니다. 애매하면 정보보호 담당 확인을 요청한다.

## 저작권·라이선스 게이트

- 공개 저장소의 `LICENSE`, 의존성 목록, 이미지·폰트 출처를 확인한다.
- 증권사 리포트 PDF, 유료 보고서, 기사 전문 등은 공개 저장소 재배포 권리를 별도로 확인한다.
- 제출 본문에는 필요한 최소한의 요약과 원 출처 링크를 사용한다.
- 사용한 오픈소스 라이브러리와 라이선스를 표로 정리한다.

## 링크 공개 전 점검

GitHub 링크를 제출하는 순간 저장소 전체가 심사 범위에 들어갈 수 있다. 원본 PDF, raw 데이터, 설정 파일, 커밋 이력까지 포함해 공개 가능성을 점검하고, 불확실하면 공개 저장소 대신 정제된 데모·문서 링크를 사용한다.

## 외부 콘텐츠 수집·외부 발송 게이트

- 뉴스·웹 수집 API 약관, 크롤링 정책, robots 조건과 재배포 범위를 확인한다.
- 유료·로그인 기사를 우회하지 않고, 기사 전문 저장·제목·본문 인용·썸네일 재사용 범위를 구분한다.
- 요약마다 원 출처와 링크를 남기고 원문으로 역추적할 수 있게 한다.
- 수신자 이메일, 메일 헤더, 발송 로그, 열람 정보는 개인정보로 취급한다.
- SMTP·메일 API 키, 배포 환경변수, 예약 작업 설정에 비밀값이 없는지 확인한다.
- 외부 발송 전 사람 승인 여부, 오발송·중복 발송·수집 급감 시 중단 기준을 기록한다.
