# 출품 양식과 평가 관점

이 문서는 재사용을 위한 요약이다. 세부 일정, 상금, 내부 운영 정보, 경쟁작 자료는 공개 저장소에 옮기지 않는다. 실제 제출 때는 사용자가 제공한 최신 공식 공지를 다시 확인한다.

## 제출 본문

### 1. 배경 및 문제 정의 (Why)

- 현업 맥락에서 왜 중요한가
- 기존 흐름은 누가, 얼마나 자주, 어떤 도구로 수행했는가
- 시간 소모, 오류, 누락, 설명 불가능성 등 구체적 Pain Point는 무엇인가
- 지금 해결해야 했던 이유는 무엇인가

### 2. 구현 방법 및 활용 Tool (How / What)

- 문제를 어떤 단계로 분해했는가
- 사용한 AI 도구와 각 도구의 실제 역할은 무엇인가
- 사람의 판단·승인과 코드가 담당한 부분은 어디인가
- 핵심 기능, 데이터 흐름, 시스템 구조, 실제 프롬프트는 무엇인가
- 결과를 어떻게 검증하고 실패를 통제하는가

도구 구분은 사용자가 실제 이용 내역을 확인한 뒤 선택한다. 저장소의 흔적만 보고 A.biz 또는 일반 부문을 추정하지 않는다.

### 3. 핵심 가치

#### Biz Impact

시간·비용·생산성·품질·리스크의 개선을 전후 비교로 제시한다. 수치는 측정 기간, 표본, 산식, 근거를 동반해야 한다.

#### 확장 가능성

다른 조직이 무엇을 준비하고 어떤 순서로 적용할 수 있는지 쓴다. 공통 엔진과 조직별로 바꿀 설정을 구분한다.

#### 혁신성

사용한 모델 이름이 아니라 기존 방식과 달라진 문제 해결·검증·의사결정 구조를 쓴다.

## 출품 적합성 게이트

- 해당 연도에 실제 구현·활용한 사례인지 확인한다. 미실행 아이디어는 사례로 단정하지 않는다.
- 사례가 여러 개면 각각 독립된 신청·본문·근거 패키지로 관리한다.
- 내부 데이터는 비식별 후에도 공개 가능성을 별도로 확인한다.
- 타인의 앱·서비스·경쟁작을 모사하지 않는다.
- 외부 라이브러리, 데이터, 이미지, 문서의 출처와 라이선스를 기록한다.
