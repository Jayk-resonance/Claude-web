# 평가자가 이해하고 기억하는 서술법

## 30초 구조

첫 화면에는 다음 네 가지가 보여야 한다.

1. 누구의 어떤 반복 문제인가
2. AI와 코드가 무엇을 바꿨는가
3. 검증된 대표 수치 하나는 무엇인가
4. 다른 조직도 왜 재사용할 수 있는가

제목은 제품명보다 변화가 먼저 오게 쓴다. 예: `CEO 주가 KPI의 계산 근거와 조건별 결과를 한 화면에서`.

## 본문 구조

`문제 장면 → 기존 흐름 → 실패 비용 → 새 흐름 → 검증 → 성과 → 재사용법` 순서가 읽기 쉽다. 기술 스택은 새 흐름을 이해하는 데 필요한 만큼만 설명한다.

공식 양식의 Why, How/What, Value 제목은 이 이야기의 이정표다. 각 항목을 독립된 답안처럼 다시 시작하지 말고, 앞 문단의 문제와 다음 문단의 해결이 자연스럽게 이어지게 쓴다. 구현 과정은 “어떻게 해결했고 왜 믿을 수 있는가”에 답하는 정도로 줄이고, 제품 기능보다 업무 변화에 더 많은 분량을 쓴다.

## 처음 보는 사람을 위한 용어

약어는 첫 등장에 전체 이름을 쓴다. 사내에서 익숙한 약어라도 평가자가 안다고 가정하지 않는다.

| 피할 표현 | 권장 표현 |
|---|---|
| SKI | SK이노베이션 |
| Peer | 비교회사 |
| immutable raw | 수집 당시 원본 데이터를 그대로 보관 |
| deterministic engine | 같은 입력이면 같은 결과가 나오는 계산 프로그램 |
| QC | 품질 점검 또는 누락·오류 점검 |
| pipeline | 작업 흐름 |
| backfill | 과거 데이터 확보 |
| simulation | 조건별 결과 비교 |
| audit trail | 결과에서 원자료까지 다시 확인할 수 있는 기록 |

기술 용어가 의미를 더 정확하게 전달하지 못하면 삭제한다. 정확성을 위해 꼭 필요하면 쉬운 설명을 먼저 쓰고 괄호 안에 용어를 덧붙인다.

## 자연스러운 문체 점검

자연스러운 글은 일부러 구어체를 섞는 글이 아니라, 작성자의 구체적인 판단과 실제 근거가 보이는 글이다.

1. 모든 문단이 “문제는”, “이를 통해”, “본 사례는”으로 시작하지 않는지 확인한다.
2. 문장 길이와 어미가 기계적으로 반복되면 합치거나 나눈다.
3. “혁신적”, “획기적”, “극대화” 같은 평가어 대신 실제로 달라진 행동과 수치를 쓴다.
4. “단순한 X가 아니라 Y”, 억지 세 항목, 내용 없는 결론을 줄인다.
5. 사용자가 제공한 표현과 판단은 살리되, 근거 없는 경험·수치·감정은 만들지 않는다.
6. 마지막으로 원문과 대조해 이름, 숫자, 날짜, 주장, 불확실성 표시가 바뀌지 않았는지 확인한다.

## 복잡한 업무를 구체적으로 보여주는 법

“복잡한 업무였다”라고만 쓰지 말고 복잡성을 만드는 실제 단위를 보여준다. 예를 들어 대상 회사 수, 데이터 기간, 계산 단계, 사업군과 가중치가 공개 가능하다면 짧은 표로 제시한다.

산식은 원식을 모두 옮기기보다 `입력 자료 → 기간별 계산 → 집단별 집계 → 상대 비교 → 점수 환산`처럼 3~5단계로 풀어 쓴다. 각 단계에서 사람이 날짜, 대상, 비중 또는 참조 수식을 잘못 적용할 수 있는 이유를 설명한다. 실제 오류가 확인되지 않았다면 “오류가 발생했다”가 아니라 “오류가 발생하기 쉬운 구조”라고 쓴다.

투명성은 평가 권한의 개방과 다르다. “누구나 평가한다” 대신 “같은 자료와 규칙을 공유받은 검토자가 계산 과정을 다시 확인하고 동일한 결과를 재현할 수 있다”라고 표현한다.

## 강한 차별화 포인트

- 원자료에서 최종 결론까지 역추적할 수 있음
- AI의 판단과 같은 입력에서 같은 결과를 내는 계산 프로그램을 분리함
- 불확실한 데이터는 숨기지 않고 경고·승인·중단 게이트로 통제함
- 한번 만든 산출물이 아니라 반복 운영 가능한 업무 흐름임
- 설정·스키마·템플릿을 바꿔 다른 조직 문제로 이전할 수 있음

## 이미지 제안

- 대표 이미지: 문제와 대표 성과 수치를 큰 글자로, 실제 제품 화면을 보조로 사용
- 과정 이미지: 기존 방식 → AI와 프로그램의 작업 흐름 → 사람 확인 → 결과
- 증거 이미지: 결과의 근거, 별도 자료를 이용한 재확인, 자동 시험 또는 전후 시간 기록
- 확장 이미지: 공통 계산 흐름과 조직별 교체 항목을 구분한 구조도

화려한 카드보다 작은 글씨를 줄이고 한 이미지에 하나의 메시지만 담는다. 실제 화면에 오류, 테스트 데이터, 민감정보가 있으면 캡처 전에 수정하거나 가린다.

## 피해야 할 문장

- `AI로 혁신했습니다` — 무엇이 어떻게 달라졌는지 없음
- `업무시간 90% 절감` — 기준, 기간, 표본, 근거 없음
- `누구나 바로 사용 가능` — 도입 전제와 운영 책임 없음
- `완전 자동화` — 사람 승인이나 미완료 단계가 존재함
- 기능 목록만 긴 문단 — 현업 가치와 연결되지 않음
- 영문 약어와 개발 용어가 이어지는 문장 — 처음 보는 평가자가 의미를 추측해야 함
- 문단마다 같은 형식의 요약·강조·결론 — 내용보다 AI 문장 틀이 먼저 보임
