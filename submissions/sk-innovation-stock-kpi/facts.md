# SK이노베이션 주가 KPI 사례 — 근거 원장

## 한 줄 포지셔닝

CEO 평가에 쓰이는 주가 KPI를 매일 확인하고, 결과의 이유와 다음 연도 기준 변경의 영향까지 한 흐름에서 검토할 수 있게 만든 사례.

## 사용자가 제공한 현업 맥락

| 주장 | 상태 | 기록 방식 |
|---|---|---|
| SK Inc.가 SK이노베이션, SK텔레콤, SK하이닉스 등 멤버사의 CEO KPI를 평가한다 | 사용자 확인 | 출품 전 공개 가능한 회사 표현과 담당 범위 확인 |
| 주가 항목은 다수 SK 멤버사가 반영하는 KPI로 판단된다 | 추론 | 실제 적용 멤버사 수와 공통·개별 기준 확인 전에는 범위를 단정하지 않음 |
| 따라서 SK이노베이션 사례의 데이터 수집·계산·검증·설명 흐름은 다른 멤버사에도 확장 가능성이 크다 | 추론 | 멤버사별 회사 목록과 평가 규칙을 바꿔 재사용하는 방향으로 기술 |

## 확인 없이는 출품문에 단정하면 안 되는 내용

| 질문 | 왜 필요한가 |
|---|---|
| 실제 사용자는 누구이며 몇 명인가 | “실제 활용 사례”와 조직 영향의 증거 |
| 기존 산출은 누가 어떤 파일로 몇 분/시간 걸려 했는가 | 시간·생산성 전후 비교의 기준선 |
| 이 시스템으로 실제 평가·보고·과제 설계에 몇 회 사용했는가 | 데모가 아닌 업무 적용 증거 |
| 오류·재작업·질의 대응 시간은 어떻게 달라졌는가 | 품질·리스크 Impact 정량화 |
| 사용한 AI 도구와 모델은 무엇인가 | 일반/A.biz 부문과 How 섹션 정확성 |
| PlayMCP 한국주식정보 연결과 개발 과정에서 사용한 실제 프롬프트는 무엇인가 | 재현 가능한 AI 활용 설명 |
| 현재 자동화가 어느 범위까지 무인 운영되는가 | 최신 `pipeline/AUTOMATION.md`와 8월 24~27일 연속 갱신 커밋은 있으나, 계획서의 오래된 미착수 표기와 차이가 있어 현재 운영 상태 확인 필요 |
| 수치와 KPI 산식을 외부 공개해도 되는가 | 공개 저장소에 이미 있어도 사내 제출·홍보 승인과는 별개 |
| SK Inc.의 멤버사 CEO KPI 평가 역할을 어디까지 공개 표현할 수 있는가 | 이번 사례의 업무 중요도를 설명하는 핵심 맥락이므로 소관부서 확인 필요 |
| 실제로 주가 KPI를 적용하는 멤버사는 몇 곳이며 공통 기준은 무엇인가 | 확장 가능성의 범위를 과장하지 않고 구체적으로 제시하기 위함 |

## 제출 전 수정 권장

1. `27년 과제 설계` 화면의 단순 종가 행에서 `—원`, `NaN%`가 노출된다. 제출용 화면 캡처 전에 수정한다.
2. CEO KPI 산식, 기준가격·점수, 비교회사와 가중치, 평가일, 다음 연도 설계 변수가 공개돼 있다. 정보보호·KPI 소관부서 승인 전에는 회사명과 수치를 가명화한 데모를 사용한다.
3. `pipeline/AUTOMATION.md`에 개인 Gmail 주소가 공개돼 있다. 제출 링크 공유 전에 제거·마스킹하고 커밋 이력 노출도 점검한다.
4. 저장소에 명시적 라이선스가 없다. 사용 오픈소스와 KIS/PlayMCP 시세 원자료의 재배포 조건, 공시 PDF·로고·폰트 출처를 정리한다.
5. “자동화”는 최신 운영 문서와 실제 실행 기록으로 확인한 범위만 표현한다. 완전 무인 운영의 기간·실패율은 사용자 확인이 필요하다.
6. 대표 이미지는 74.24점 같은 당일 값보다 `9종목·11개월·결측 0건·원자료 역추적`처럼 지속되는 증거를 중심으로 구성한다.
