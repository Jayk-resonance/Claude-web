# 사례명 후보

1. **53점의 변수까지 밝혀낸 CEO 주가 KPI 감사추적·시뮬레이션 시스템**
2. **수작업 KPI 계산을 원자료까지 추적 가능한 의사결정 시스템으로**
3. **9종목·11개월 데이터를 결측 없이 연결한 CEO 주가 KPI Copilot**

현재 추천은 2번이다. 처음 보는 사람도 문제와 변화를 이해하기 쉽고, 확정되지 않은 “AI 완전 자동화”를 과장하지 않는다. 1번은 대표 이미지의 보조 카피로 강하다.

## 사례 개요 초안

CEO 주가 KPI는 SK이노베이션과 8개 Peer의 기간별 거래량가중평균, 그룹 가중치, 상대성과, 점수 환산을 순서대로 계산해야 해 결과를 빠르게 설명하고 산식 변경 영향을 비교하기 어려웠습니다. 이를 원자료 수집, 결정적 Python 계산, 교차검증, GitHub Pages 시각화로 분리해 9종목·11개월 데이터를 하나의 추적 가능한 흐름으로 연결했습니다. 실제 비교 과정에서는 거래량가중 산식 차이보다 평가 기간 선택이 특정 기준일 점수를 최대 53점 바꿀 수 있음을 발견했고, 2027년 과제 설계 조건을 화면에서 즉시 비교할 수 있게 했습니다. `[확인 필요: 실제 활용 횟수와 시간 절감 성과]`

## 1. 배경 및 문제 정의 (Why)

### 현업 맥락

CEO KPI의 주가 평가는 단순 종가 확인이 아니라 SK이노베이션과 Peer 8개사의 기간별 평균주가, 두 사업군의 상대성과, 기준가격 대비 점수 환산을 결합하는 업무입니다. 최종 점수만 전달하면 “어느 종목과 어떤 기간이 점수를 바꿨는지”, “평가 조건을 바꾸면 결과가 어떻게 달라지는지”를 즉시 설명하기 어렵습니다.

### As-Is와 Pain Point

- 여러 종목과 기간의 데이터를 반복 수집·정리해야 한다. `[확인 필요: 기존 도구와 소요시간]`
- 거래량가중평균의 정의, 평가 기간, 기준선이 달라질 때 결과 차이를 손으로 비교하기 어렵다.
- 최종 숫자에서 원자료와 중간 산식으로 거슬러 올라가는 감사 추적이 약하면 질의 대응과 검증에 시간이 든다. `[확인 필요: 실제 오류·재작업 사례]`
- 다음 연도 과제 설계 시 조건별 민감도를 한 화면에서 비교하기 어렵다.

### 해결 목표

단순히 점수를 계산하는 도구가 아니라, 같은 원자료로 재현 가능한 계산 엔진과 검증 근거를 남기고, 평가 조건의 영향을 의사결정자가 직접 비교하는 시스템을 만드는 것을 목표로 했습니다.

## 2. 구현 방법 및 활용 Tool (How / What)

### 해결 접근

`수집 → 정규화 → 결정적 계산 → 품질검사·교차검증 → 대시보드 데이터 생성 → GitHub Pages 배포`로 흐름을 분리했습니다. AI 연결은 데이터 수집과 개발·분석을 보조하고, 최종 점수 계산은 저장된 원자료를 입력받는 Python 코드와 테스트가 담당하도록 해 같은 입력에서 같은 결과가 나오게 했습니다.

### 활용 AI Tool과 실제 역할

| 도구 | 실제 역할 | 상태 |
|---|---|---|
| PlayMCP 한국주식정보 | 9종목의 일별 주가·거래량·거래대금 수집 | 공개 수집 규격과 PLAN에서 확인 |
| Codex 반복 작업 | 일일 수집·검증·사이트 갱신 흐름 오케스트레이션 | 최신 `pipeline/AUTOMATION.md`에서 확인; 실제 무인 운영 범위는 사용자 확인 |
| Claude | 초기 시스템 구현과 설계 보조 | 커밋 기록과 PLAN에서 확인; 사용 모델·대표 프롬프트는 사용자 확인 |
| Python + pytest | 산식 계산, 데이터 검증, 회귀 테스트 | 저장소에서 확인 |
| GitHub Pages | 정적 대시보드 공개·배포 | 실제 사이트 확인 |

### 시스템 구조

`주가 원자료 → immutable raw 데이터 → 정규화 CSV → 순수 Python KPI 엔진 → QC/교차검증 → JSON → 정적 대시보드`

핵심은 AI가 계산 결과를 문장으로 “그럴듯하게” 만드는 구조가 아니라, AI가 수집·개발을 돕고 계산은 테스트 가능한 코드가 책임지는 역할 분리입니다.

### 핵심 기능

- 9종목의 현재가와 기간별 추세를 한 화면에서 비교
- 거래량가중평균 두 방식과 여러 평가 기간을 같은 데이터로 대조
- SK 자체 성과와 Peer 상대성과가 평가주가에 미친 영향을 단계별로 분해
- 2027년 과제 설계 조건을 바꾸면 점수와 기준가격을 즉시 재계산
- CSV·PNG 내보내기, 점수 시계열, 데이터 신뢰도 경고

### 실제 프롬프트

`[확인 필요: 민감정보를 제거한 실제 대표 프롬프트 2~3개. 요구사항 정의, 데이터 수집, 검증·버그 수정 사례를 각각 하나씩 권장]`

### 검증과 안전장치

- 수집·계산·배포를 분리해 저장된 원자료로 재계산 가능
- 산식 항등식과 평가 로직을 pytest로 고정
- 수집 공백·결측·급변·기업행사 위험을 검사하고 이상 시 공개 데이터 갱신을 중단하도록 설계
- 공식 기준값이 데이터로 재현되지 않는 한계를 숨기지 않고 화면에 경고
- 분기 평가 시 원자료, 중간 계산, 코드 커밋을 묶어 제3자가 추적 가능한 산출근거 패키지를 생성

## 3. 핵심 가치 (Value Proposition)

### 3-1. Biz Impact

현재 공개 근거만으로 입증 가능한 성과는 `9종목 × 11개월 데이터, 수집 공백·결측 0건`, `산식 정의 차이의 점수 영향 1점 미만`, `평가 기간 선택의 특정 기준일 영향 최대 53점 발견`입니다. 그러나 좋은 평가를 위해서는 제품 지표가 아니라 업무 성과가 필요합니다.

|---|---:|---:|---|
| 1회 KPI 산출·검증 시간 | `[확인 필요]` | `[확인 필요]` | 작업 로그 또는 캘린더 표본 |
| 조건 변경 시 시나리오 비교 시간 | `[확인 필요]` | `[확인 필요]` | 동일 조건 전후 측정 |
| 원자료·산식 질의 대응 시간 | `[확인 필요]` | `[확인 필요]` | 실제 질의 사례 |

### 3-2. 확장 가능성

종목, 그룹, 가중치, 평가 기간, 기준가격을 설정 파일로 분리했고, 수집·계산·검증·배포 단계를 모듈화했습니다. 다른 멤버사는 자기 회사와 Peer, KPI 산식, 데이터 연결만 교체하고 계산·검증·시각화 패턴을 재사용할 수 있습니다. 도입 순서는 `한 평가 시점의 수기 결과와 대조 → 과거 데이터 백필 → 품질 게이트 → 시나리오 화면 → 운영 자동화`가 안전합니다.

### 3-3. 혁신성

차별점은 대시보드 자체보다 “설명 가능한 KPI 운영 구조”입니다. AI 기반 수집과 사람이 이해할 수 있는 화면 사이에 결정적 계산 엔진과 교차검증 게이트를 두고, 불확실한 기준값은 감추지 않고 경고합니다. 또한 산식 A/B 논쟁보다 평가 기간 선택이 결과를 훨씬 크게 바꾼다는 사실을 실제 데이터로 발견해, 단순 현황 조회를 다음 연도 KPI 설계 도구로 확장했습니다.
