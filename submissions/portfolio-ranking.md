# 첨부 경쟁작 벤치마크 우선순위

이 순위는 사용자가 첨부한 경쟁작 카드에서 **눈으로 확인되는 제목, 대표 이미지, 정량 수치, 제품 흐름**만 기준으로 정한 것이다. 좋아요 수는 지인 효과가 있을 수 있으므로 평가 근거에서 제외했다. 카드만으로 실제 성과의 정확성이나 최종 수상 가능성을 확정하지 않는다.

## 1순위 — 새는 전기료를 잡아냅니다! `SAVE-E`

### 카드에서 확인되는 강점

- 현업 문제가 `새는 전기료`라는 쉬운 언어로 즉시 이해된다.
- 대표 화면에 `5,428만원`, `75.8%`, `10분 → 3초`가 크게 제시돼 비용·개선율·시간을 동시에 전달한다.
- 설비 이미지와 분석 대시보드를 함께 보여 문제 대상과 실제 결과물을 연결한다.
- “전기료 절감”은 비용 절감이라는 명확한 Biz Impact로 바로 이어진다.

### 벤치마킹할 것

1. 제목을 `현업의 손실 → 해결 결과` 구조로 만든다.
2. 대표 이미지에 가장 강한 성과 수치 2~3개만 크게 배치한다.
3. 실제 설비·업무 대상과 제품 화면을 한 장에서 연결한다.
4. 본문에서는 절감액이 실현액인지 예상액인지, 측정 기간·대상·산식을 증명한다.

### 그대로 따라 하면 안 되는 것

- 수치의 기간·기준·근거 없이 큰 숫자만 배치하는 방식
- 실제 절감과 시뮬레이션 예상 절감을 구분하지 않는 표현
- 해당 작품의 색상, 레이아웃, 문구를 복제하는 것

## 2순위 — AI가 계속 레시피를 씁니다

### 카드에서 확인되는 강점

- `2.65일 → 0.5일`, `117 / 120건`, `모든 Lot 실무 적용`이 한 화면에 보인다.
- 속도 개선뿐 아니라 처리 규모와 실제 현업 적용 범위를 함께 제시한다.
- “말로 시키고 그림으로 그리면 자동화가 만들어진다”는 구현 접근이 짧게 설명된다.
- 검은 배경과 녹색 숫자를 사용해 성과가 기능 설명보다 먼저 읽힌다.

### 벤치마킹할 것

1. `시간 개선 → 처리 커버리지 → 실제 적용`의 3단 증거 구조를 사용한다.
2. 데모가 아니라 실무 적용 사례라는 증거를 전면에 둔다.
3. AI 역할을 제품명 나열이 아니라 사람이 지시하고 시스템이 반복 수행하는 흐름으로 설명한다.
4. 본문에서 미적용 건의 사유와 사람 검수·예외 처리까지 밝혀 신뢰도를 높인다.

### 우리 KPI 사례에 적용한다면

`산출·검증 소요시간`, `9종목·11개월 데이터 커버리지`, `실제 보고·평가 적용 횟수`를 같은 구조로 보여줄 수 있다. 단, 시간 절감과 실제 적용 횟수는 사용자의 측정 근거가 필요하다.

## 3순위 — 사진 한 장으로 시작하는 사내 구매요청 플랫폼

### 카드에서 확인되는 강점

- 제목만으로 입력 방식과 해결 업무가 모두 이해된다.
- 모바일 사진 입력과 데스크톱 업무 화면을 함께 보여 전체 사용자 여정을 직관적으로 설명한다.
- 복잡한 구매요청을 `사진 한 장`이라는 한 번의 행동으로 축약해 진입 장벽을 낮춘다.
- 카드가 제품 화면 중심이라 처음 보는 사람도 실제로 구현된 결과물임을 바로 알 수 있다.

### 벤치마킹할 것

1. 핵심 기능을 사용자의 첫 행동 하나로 표현한다.
2. 입력 → AI 처리 → 업무 결과를 한 장의 흐름으로 보여준다.
3. 모바일과 업무용 화면을 함께 사용해 실제 사용 상황을 전달한다.
4. 본문에는 요청 작성시간, 반려율, 재입력 횟수, 실제 사용자 수처럼 카드에서 부족한 Biz Impact를 보강한다.

### 우리 KPI 사례에 적용한다면

제목을 기술 용어보다 사용자의 행동과 결과로 바꿀 수 있다. 예: `평가일만 선택하면 원자료부터 CEO 주가 KPI 점수까지 추적합니다`.

## 차선 벤치마크

- **LabHub**: 여러 업무를 하나의 플랫폼으로 통합하고 현업 연구원이 AI와 직접 만들었다는 제작 서사를 참고할 만하다. 다만 카드만으로는 정량 Biz Impact가 약하다.
- **1분 만에 찾는 데이터: 자연어 기반 사내 데이터 카탈로그 Agent**: 시간 약속이 제목에 들어가고 실제 대시보드를 크게 보여주는 방식이 좋다. `1분`의 측정 근거가 본문에서 필요하다.
- **주유소 제휴 신용카드 정산 Agent**: 누구나 이해하는 반복 정산 Pain Point와 입력→Agent→결과 흐름을 한 장에 담은 방식이 참고할 만하다.

## 세 작품에서 공통으로 가져올 원칙

| 벤치마크 요소 | 우리 출품에 적용할 방식 |
|---|---|
| 3초 안에 이해되는 제목 | `수작업 KPI 계산을 원자료까지 추적 가능한 의사결정 시스템으로` |
| 대표 숫자 2~3개 | 검증된 수치만 사용: 9종목, 11개월, 결측 0건. 시간 절감은 측정 후 추가 |
| 제품 화면과 과정 동시 제시 | KPI 평가 화면 + 수집→계산→검증→배포 구조 |
| 실제 적용 증거 | 사용 조직, 활용 횟수, 보고·의사결정 사례를 사용자에게 확인 |
| 전문가 검증 가능성 | 수치마다 기준값·기간·표본·산식·근거 위치 제공 |

핵심은 시각 스타일을 따라 하는 것이 아니라, `한 문장 문제 정의 + 검증된 숫자 + 실제 제품 + 재현 가능한 근거`의 정보 구조를 벤치마킹하는 것이다.
